# Как бесплатно дать другу поиграть через Telegram

Проверено по документации провайдеров 3 ноября 2026. Подходит для небольшого закрытого теста: **Render Free** запускает сервер и интерфейс, **Neon Free** хранит PostgreSQL, Telegram открывает игру. Твой компьютер после публикации не нужен. Это инструкция и подготовленная конфигурация; аккаунты, бот и публичное размещение автоматически не создавались.

## 1. Выбрать ветку с мобильной игрой

Для деплоя используйте ветку `main` репозитория `Shawndas06/game_stateg`: в неё объединены история проекта из `develop` и новая мобильная версия. Render получает код из выбранной удалённой ветки. Последующие изменения проходят через PR и обязательные проверки. После слияния main проверяется повторно; Render с настройкой After CI Checks Pass запускает автодеплой после успешного окончания проверок этого коммита.

В репозитории должны оказаться `campaign/`, `server/`, `web/`, `requirements-server.txt`, `Dockerfile` и `render.yaml`. Не отправлять `.env`, `saves/`, виртуальное окружение и локальные журналы. Они исключены из Git/образа; токены вводятся в настройках Render.

## 2. Создать бесплатную базу Neon

1. Зарегистрироваться на [Neon](https://neon.com/pricing), выбрать **Free** и создать проект PostgreSQL.
2. Выбрать регион, доступный также у Render, чтобы уменьшить задержку.
3. В **Connect** скопировать только строку подключения для своей базы: начиная с `postgresql://`, без команды `psql` и внешних кавычек. Для маленького теста достаточно прямого подключения, без включения дополнительных сервисов.
4. В начале строки заменить только `postgresql://` на `postgresql+psycopg://`. Пароль, адрес, имя базы и SSL-параметры оставить как выданы. Эта строка станет `DATABASE_URL` в Render.

Схематический формат, это не рабочие учётные данные:

```text
postgresql+psycopg://USER:PASSWORD@HOST/DATABASE?sslmode=require
```

У Free сейчас1 GB базы и100 CU-часов в месяц на проект; это не пробный тариф с30-дневным сроком. При неактивности вычисления засыпают, данные сохраняются. [Тариф и ограничения Neon](https://neon.com/pricing).

## 3. Создать бота

В Telegram открыть [@BotFather](https://t.me/BotFather), отправить `/newbot`, задать имя и username. Полученный токен потребуется только в Render как `TELEGRAM_BOT_TOKEN`. Отдельный процесс, который постоянно опрашивает Telegram, этой игре не нужен: вход проверяет существующий сервер Mini App.

Не публиковать токен и строку базы в репозитории, скриншотах или сообщениях другу.

## 4. Развернуть Render Free

1. Зарегистрироваться на [Render](https://render.com/docs/free), подключить свой GitHub.
2. **New → Blueprint**, подключить репозиторий `Shawndas06/game_stateg`, выбрать ветку **main**. Blueprint Path — **render.yaml** в корне проекта. Render прочитает готовую конфигурацию; отдельные Build Command и Start Command задавать не требуется.
3. Проверить, что создаётся один **Web Service**, runtime **Docker**, тариф **Free**. Платный диск и базу Render не добавлять.
4. При настройке ввести `DATABASE_URL` из Neon и `TELEGRAM_BOT_TOKEN` из BotFather. `APP_ENV=production` уже указан, `SESSION_SECRET` генерируется автоматически и должен оставаться постоянным между перезапусками.
5. Выполнить создание/первое развёртывание и дождаться **Live**. Если первый запуск не начался автоматически, выбрать **Manual Deploy → Deploy latest commit**.
6. Скопировать выданный HTTPS-адрес вида `https://ИМЯ.onrender.com`. Игра автоматически берёт его из `RENDER_EXTERNAL_URL`; заранее угадывать адрес не нужно. Для своего домена можно явно задать `PUBLIC_URL` и перезапустить сервис.
7. Открыть `/api/health` по этому адресу: должен вернуться `status: ok`. При ошибке посмотреть вкладку Logs; секреты не копировать в публичные сообщения.

Автообновление по каждому коммиту в шаблоне выключено: новые версии публикуются вручную после проверки. [Документация Blueprint](https://render.com/docs/blueprint-spec), [переменные Render](https://render.com/docs/environment-variables).

## 5. Подключить кнопку игры и отправить другу бота

В BotFather отправить `/setmenubutton`, выбрать бота, задать подпись **Играть** и HTTPS-адрес из Render. Друг открывает чат с ботом и нажимает кнопку меню **Играть**. Поддержка такого запуска описана в [документации Telegram](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button).

Для первой проверки открывать игру именно этой кнопкой внутри Telegram. Обычная вставленная ссылка в браузере не передаёт подписанные данные входа; публичный режим намеренно не включает локальный демонстрационный вход. Ответ на `/start` отдельным сообщением пока не реализован; запуск выполняет настроенная кнопка меню.

У каждого Telegram-пользователя своя одиночная кампания. Это не общий многопользовательский мир. Друг не увидит твои локальные сохранения: в новой Neon-базе он начнёт свою партию.

## Ограничения нулевого бюджета

Render Free засыпает после15 минут без обращений; первое открытие после сна может занять около минуты. При превышении бесплатных лимитов сервис может приостановиться. Выбирать только Free, не включать платные ресурсы; при отсутствии способа оплаты превышение лимитов приводит к ограничениям, а не автоматической оплате. Если регистрация потребует платный тариф или недоступную проверку, эта инструкция не гарантирует возможность обойти требования аккаунта. [Официальные ограничения Render](https://render.com/docs/free).

SQLite на Render Free использовать нельзя для сохраняемых партий: локальные изменения диска пропадают после сна/перезапуска. Бесплатный PostgreSQL самого Render истекает через30 дней, поэтому здесь предложен Neon. Ни свой домен, ни VPS, ни Redis, ни платный ИИ для этого теста не требуются. Сохранения находятся во внешней базе; её удаление потеряет партии, поэтому перед удалением проекта или сменой базы нужно отдельно сохранить данные.

## Что проверить после публикации

1. Ты и друг входите через кнопку бота, начинаете разные партии и видите только свои сохранения.
2. Друг принимает решение, закрывает Telegram и снова открывает игру: партия продолжается.
3. После сна Render и после ручного перезапуска партия остаётся доступной в Neon.
4. Интерфейс и числовые поля работают на настоящем телефоне. Это отдельная проверка: локальные Chromium/WebKit её полностью не заменяют.

Конфигурация Blueprint проверена по официальной JSON-схеме. Код игры прошёл [GitHub Actions](https://github.com/Shawndas06/game_stateg/actions/runs/41685990665): 217 серверных тестов с PostgreSQL, сборку и запуск Docker, сценарные прохождения и мобильные Chromium/WebKit. При объединении в main игровой код сохранён без изменений. Подключение именно к твоей Neon-базе, размещение в твоём Render и настоящий Telegram WebView ещё предстоит проверить. Это версия для закрытого тестирования: полная историческая кампания до 1453 года не завершена.
